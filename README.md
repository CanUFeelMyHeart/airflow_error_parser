# Парсер ошибок DDL

Инструмент для анализа ошибок выполнения SQL-скриптов, классификации проблем и формирования итогового отчёта.

## v1

**Дата:** 06.11.2026

### Описание

Версия парсера предназначена для обработки CSV-файла с ошибками выполнения SQL-скриптов. Программа анализирует текст ошибок, определяет их категорию, группирует записи и формирует итоговый CSV-файл.

### Реализованная функциональность

**1. Чтение исходного CSV-файла**

- Чтение файла с разделителем `;`.
- Пропуск строки заголовка.
- Извлечение пути к SQL-файлу и текста ошибки.
- Объединение оставшихся полей CSV в единый текст ошибки.

**2. Классификация ошибок**

Реализована функция `classify_error()`, которая определяет категорию ошибки на основании поиска заданных фрагментов текста.

Предусмотрено 11 категорий:

| Категория | Описание |
|---|---|
| `PARTS_63` | Повторяющееся название таблицы партиции при превышении длины в 63 символа |
| `PARTS_DONT_GEN` | Не генерируются значения для списковых партиций |
| `NOT_SOURCE` | Отсутствует источник |
| `NOT_CTE` | Отсутствует CTE |
| `NOT_FIELD` | Отсутствует поле |
| `SYNTAX` | Синтаксическая ошибка |
| `UNDEFINED` | Неизвестная ошибка |
| `NOT_SETTINGS_TABLE` | Отсутствуют атрибуты таблицы в `system_core.sys_object_attrs` |
| `INVALID_STRUCTURE` | Невалидное формирование партиций |
| `NOT_TASK_GROUP_CODE` | Отсутствует `task_group_code` в метаданных |
| `NOT_SETTINGS_ATTR` | Отсутствует атрибут в `system_core.sys_object_attrs` |

Для отдельных категорий дополнительно извлекается контекст: имя таблицы, CTE, поля, схемы или атрибута.

**3. Формирование описания ошибок**

Для каждой категории предусмотрено формирование двух текстовых значений:
- `was` — описание обнаруженной проблемы.
- `to` — предполагаемое направление устранения ошибки.

Для части категорий используются предварительные рекомендации или пометки `TODO`, указывающие на необходимость дополнительного анализа.

**4. Группировка ошибок**

Записи группируются по определённым категориям с использованием `defaultdict`. Для каждой записи сохраняются дата обработки, путь к файлу, категория ошибки и сформированные текстовые описания.

**5. Формирование итогового CSV-файла**

Результаты записываются в файл `errors_agg.csv` с разделителем `;` и кодировкой `UTF-8-SIG`.

В итоговый файл записываются:
- дата обработки;
- имя объекта;
- категория ошибки;
- три зарезервированных пустых поля;
- описание проблемы (`was`);
- предполагаемое решение (`to`).

Записи располагаются группами по категориям ошибок. Заголовок итогового CSV-файла не формируется.

**6. Вывод статистики**

В консоль выводятся:
- общее количество прочитанных записей;
- количество ошибок в каждой категории.

## v2 (от 09.11.2026)

### Основные изменения

| Область | Изменения в V2 |
|---|---|
| Классификация | Переработана система категорий ошибок. Используются технические идентификаторы вместо текстовых названий. |
| Извлечение зависимостей | Добавлена отдельная функция `extract_dependency()` для извлечения имён объектов, полей, партиций и других зависимостей из текста ошибки. |
| Описание проблем | Добавлена функция `get_problem_string()` для формирования структурированного описания каждой ошибки. |
| Определение объектов | Добавлена функция `path_obj()` для извлечения схемы и имени объекта из пути к SQL-файлу. |
| Статусы | Добавлено определение уникальных, дублирующихся и неактуальных ошибок. |
| Проверка партиций | Добавлена отдельная проверка ошибок, связанных с длиной имени партиции. |
| Статистика | Добавлен подробный вывод в консоль: общее количество ошибок, количество объектов, распределение по категориям и статусам, ТОП-10 объектов. |
| Итоговый отчёт | Добавлены заголовки, порядковый номер, статус, описание проблемы и исходный текст ошибки. Каждая ошибка записывается отдельной строкой. |
| Обработка файлов | Добавлена проверка существования входного файла и автоматическое создание выходной директории. |
| Запуск | Обработка объединена в функцию `run_parser()`. Версия адаптирована для запуска в Jupyter Notebook. |

### Изменения в классификации

В V2 изменена структура категорий:

- `NOT_SOURCE` и `NOT_CTE` объединены в `missing_relation`. Различие определяется при формировании описания проблемы.
- `PARTS_63` заменена на `relation_already_exists` с дополнительной проверкой ошибок партиций.
- `NOT_FIELD` заменена на `missing_column`.
- `NOT_TASK_GROUP_CODE` заменена на `task_group_not_registered`.
- `NOT_SETTINGS_TABLE` заменена на `object_attr_not_registered`.
- Остальные категории также приведены к единому формату технических идентификаторов.

## Запуск и настройка

Для запуска парсера предусмотрены два варианта:
- Google Colab — запуск в браузере без локальной установки Python и Jupyter.
- Jupyter Notebook / JupyterLab — запуск на локальном компьютере.

Обе версии парсера запускаются в формате Jupyter Notebook (`.ipynb`).

### 1. Google Colab

1. Открыть [Google Colab](https://colab.research.google.com/).
2. Загрузить файл ноутбука `.ipynb` через меню «Файл» → «Загрузить блокнот».
3. Загрузить исходный CSV-файл с ошибками в среду Colab. Для этого открыть вкладку «Файлы» и нажать «Загрузить».
4. Открыть первую ячейку ноутбука и изменить пути к файлам.

**Настройка V1:**

```python
INPUT_CSV = "/content/errors.csv"
OUT_CSV = "/content/errors_agg.csv"
```

**Настройка V2:**

```python
INPUT_CSV = Path("/content/errors.csv")
OUT_CSV = Path("/content/errors_report.csv")
```

Где:
- `INPUT_CSV` — путь к исходному CSV-файлу с ошибками.
- `OUT_CSV` — путь и имя итогового CSV-файла.

5. Выполнить все ячейки ноутбука последовательно через меню «Среда выполнения» → «Выполнить все».

6. После завершения обработки проверить вывод статистики в последней ячейке.

7. Скачать итоговый CSV-файл из вкладки «Файлы». Для этого нажать правой кнопкой мыши на файл и выбрать «Скачать».
### 2. Локальный Jupyter Notebook / JupyterLab

1. Установить Python 3.
2. Установить Jupyter Notebook или JupyterLab:

```bash
pip install notebook jupyterlab
```

3. Запустить Jupyter Notebook:

```bash
jupyter notebook
```

Или JupyterLab:

```bash
jupyter lab
```

4. Открыть файл ноутбука `.ipynb`.
5. Разместить исходный CSV-файл в доступной директории.
6. Изменить пути к файлам в первой ячейке ноутбука.

**Настройка V1:**

```python
INPUT_CSV = r"D:\parser\errors.csv"
OUT_CSV = r"D:\parser\errors_agg.csv"
```

**Настройка V2:**

```python
INPUT_CSV = Path(r"D:\parser\errors.csv")
OUT_CSV = Path(r"D:\parser\errors_report.csv")
```

7. Выполнить все ячейки ноутбука последовательно.
8. Проверить статистику обработки и наличие итогового CSV-файла в указанной директории.
