# Парсер ошибок

## v1

### Описание

Версия парсера предназначена для обработки CSV-файла с ошибками выполнения SQL-скриптов. Программа анализирует текст ошибок, определяет их категорию, группирует записи и формирует итоговый CSV-файл.

### Реализованная функциональность

**1. Чтение исходного CSV-файла**

- Чтение файла с разделителем `;`.
- Пропуск строки заголовка.
- Извлечение пути к SQL-файлу и текста ошибки.
- Объединение оставшихся полей CSV в единый текст ошибки.

**2. Классификация ошибок**

Реализована функция `classify_error()`, которая определяет категорию ошибки на основании поиска заданных фрагментов текста.

Предусмотрено 11 категорий:

| Категория | Описание |
|---|---|
| `PARTS_63` | Повторяющееся название таблицы партиции при превышении длины в 63 символа |
| `PARTS_DONT_GEN` | Не генерируются значения для списковых партиций |
| `NOT_SOURCE` | Отсутствует источник |
| `NOT_CTE` | Отсутствует CTE |
| `NOT_FIELD` | Отсутствует поле |
| `SYNTAX` | Синтаксическая ошибка |
| `UNDEFINED` | Неизвестная ошибка |
| `NOT_SETTINGS_TABLE` | Отсутствуют атрибуты таблицы в `system_core.sys_object_attrs` |
| `INVALID_STRUCTURE` | Невалидное формирование партиций |
| `NOT_TASK_GROUP_CODE` | Отсутствует `task_group_code` в метаданных |
| `NOT_SETTINGS_ATTR` | Отсутствует атрибут в `system_core.sys_object_attrs` |

Для отдельных категорий дополнительно извлекается контекст: имя таблицы, CTE, поля, схемы или атрибута.

**3. Формирование описания ошибок**

Для каждой категории предусмотрено формирование двух текстовых значений:
- `was` — описание обнаруженной проблемы.
- `to` — предполагаемое направление устранения ошибки.

Для части категорий используются предварительные рекомендации или пометки `TODO`, указывающие на необходимость дополнительного анализа.

**4. Группировка ошибок**

Записи группируются по определённым категориям с использованием `defaultdict`. Для каждой записи сохраняются дата обработки, путь к файлу, категория ошибки и сформированные текстовые описания.

**5. Формирование итогового CSV-файла**

Результаты записываются в файл `errors_agg.csv` с разделителем `;` и кодировкой `UTF-8-SIG`.

В итоговый файл записываются:
- дата обработки;
- имя объекта;
- категория ошибки;
- три зарезервированных пустых поля;
- описание проблемы (`was`);
- предполагаемое решение (`to`).

Записи располагаются группами по категориям ошибок. Заголовок итогового CSV-файла не формируется.

**6. Вывод статистики**

В консоль выводятся:
- общее количество прочитанных записей;
- количество ошибок в каждой категории.
